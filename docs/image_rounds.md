# OMuse 图像能力 · 10 轮对标测试记录（对标 Midjourney / DALL·E）

基线（2026-10-07，0.2.74）：OMuse **没有任何图像生成/编辑能力**（只有数据图表 make_chart、网页存图、截图）。
后端选择：用户决定 **先不接图像模型后端**。因此每轮的「能力」做进代码并用模拟的 OpenAI / DALL·E / 本地 SD 服务器做单元测试；
**凡是依赖真模型出图质量的验证统一记为「待后端」**；不需要模型的能力（加字、放大、降级路径）在盒子上实测。
发布：10 轮合并发布为 0.2.75（浏览器终端部署极不稳定，分 10 次发布不现实）。

| 轮 | 方向 | 结果 | 发布 |
|---|---|---|---|
| 1 | 文生图地基 | ✅ 修复：新增 make_image，OpenAI Images 兼容、自动选模型、无后端清晰提示 | 0.2.75 |
| 2 | 画幅 / 尺寸 / 多张 / 质量 | ✅ 修复：square/landscape/portrait + 任意比例 + 明确尺寸；各家尺寸自动回退；n≤4；quality 不支持自动丢弃 | 0.2.75 |
| 3 | 风格控制 | ✅ 修复：17 个风格预设（中英文触发词 → 具体提示词），negative_prompt 通道 | 0.2.75 |
| 4 | 局部重绘 inpainting | ✅ 修复：edit_image + mask（透明=重画区）；⚠️ 记录：聊天里没有「涂抹选区」画笔 | 0.2.75 |
| 5 | 图生图 / 风格参考 | ✅ 修复：edit_image 多图输入（references）；⚠️ 记录：--sref 风格码无 API 等价物 | 0.2.75 |
| 6 | 变体与迭代 | ✅ 修复：vary_image（/variations 优先，否则 edit 回退）；对话式迭代（记住最近一张，不用传 path） | 0.2.75 |
| 7 | 放大 / 高清 | ⚠️ 部分：upscale_image 本机 2x/4x 像素放大 + 锐化；**记录：真正 AI 超分需专门模型，无** | 0.2.75 |
| 8 | 图中文字 | ✅ 修复（绕开模型）：caption_image 本机排版、字对字准确、支持中文（浏览器容器渲染，已真实验证） | 0.2.75 |
| 9 | 实用产出 | ✅ 修复：透明背景、png/jpeg/webp、logo/产品图预设、send=false 供 make_pdf 引用、Telegram 走 send_file | 0.2.75 |
| 10 | 安全与稳健 | ✅ 修复：审核拒绝/超时/未配置都给「不要重试」的清晰提示；prompt 去控制字符+截断；工作区路径越界拒绝；审计事件 | 0.2.75 |

## 汇总：记下来的（不能修 / 待后端）
1. **真实出图质量、风格保真、角色一致性** — 全部待接后端（用户选择暂不接）。
2. **聊天内涂抹选区画笔**（MJ Editor / ChatGPT 选区）— 需要前端 UI 工作，本批未做；替代：文字描述改或 mask PNG。
3. **AI 超分** — 无模型，只有像素放大。
4. **MJ 私有能力**：--sref 风格码、--stylize 数值、个性化画风、图生视频 — 无 API 等价物。
5. **Vary 的 Subtle/Strong 强度档** — 无通用参数，用提示词近似。
6. **按张计费的预算上限** — 接后端时补。
